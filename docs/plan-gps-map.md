# 개발 기획 — GPS 좌표 지도 표시 (사진 위치 보기)

> 상태: **검토 중 (미구현)**. 본 문서는 사전 조사 결과 + 구현안 + **Windows 빌드 PC 검증 체크리스트**임.
> 작성: 2026-06-08. 조사 환경: Linux 개발기(샘플은 파나소닉 RW2 + Sony ARW, **GPS 데이터 없는 샘플뿐**).

## 0. 요청 요약

- 파일에 GPS(위치) 데이터가 있으면 **지도 위에 촬영 위치를 표시**.
- 성능: 빠르게 뜰 필요 없음. **기존 사진 보기가 다 빠르게 뜬 뒤, 유휴 상태에서 로딩 시작**.
- **토글 가능**해야 함(on/off).

## 1. 결론 (먼저)

- **가능. AF 포인트(#37)와 난이도가 정반대로 쉬움.**
- GPS는 제조사 MakerNote가 아니라 **표준 EXIF(GPS IFD)**에 있음. **현재 쓰는 `kamadak-exif`(0.6.1)가 이미 완전 지원** → 좌표 추출은 추가 의존성 0.
- 진짜 관건은 "지도 표시 방법". **#33에서 넣은 `ureq`를 재사용**하면 무거운 런타임(tokio) 없이 인앱 지도가 됨 → **권장안**.
- 단, **개발기 샘플엔 GPS가 하나도 없음**(파나소닉 S1R II/S1 II는 GPS 모듈 없음, 폰 연동 시에만 기록) → **Windows에서 GPS 태깅된 사진으로 검증 필요**.

## 2. 추출 — 이미 가능 (확인됨)

- `kamadak-exif` 소스에서 확인: `Context::Gps`, `GPSLatitude/Longitude/Altitude`,
  `GPSLatitudeRef/LongitudeRef`, `GPSInfoIFDPointer(0x8825)` 모두 정의돼 있음.
- 위경도는 도/분/초(rational ×3) + 반구 기호(N/S, E/W)로 저장 → 십진수 변환만 하면 됨.
- 기존 EXIF 경로(`meta.rs` `read_exif`)가 컨테이너 + 임베디드 JPEG 폴백을 이미 갖고 있어,
  **`ExifInfo`에 lat/lon/alt 필드만 추가**하면 RW2 등도 동일 폴백으로 처리됨.
- 데이터 없는 사진(대부분의 RAW)은 자연히 좌표 없음 → 지도 미표시.

## 3. 표시 방법 — 선택지

> egui 0.29 + 단독 바이너리(무거운 런타임 회피) 기준.

| 방식 | 인앱 표시 | 의존성 부담 | 요구(지연로딩·토글) 부합 | 비고 |
|---|:---:|---|:---:|---|
| **인앱 정적 지도 (ureq + OSM 타일)** ⭐ | ✅ | **없음**(ureq 재사용) | ✅ 정확히 맞음 | **권장** |
| 외부 브라우저 "지도에서 보기" | ❌ | 없음 | △ | 가장 단순, 즉시. 보조로 병행 가능 |
| `walkers`(egui 슬리피맵) | ✅ | **tokio+reqwest 끌어옴** | ✅ | egui 0.29 호환은 묵은 0.25.0뿐. 철학 위배 → 비권장 |
| `egui-map-view` | ✅ | 미확인 | — | egui 0.34 필요 → **현재 채택 불가** |

- **외부 브라우저 URL 패턴**(보조 기능용):
  `https://www.openstreetmap.org/?mlat={lat}&mlon={lon}#map=15/{lat}/{lon}`
- 정적 이미지 API(Geoapify 등)는 API 키·유료화 리스크 → 비권장.

## 4. 권장 구현안 (인앱 정적 지도, ureq 재사용)

사용자 요구("사진 다 뜬 뒤 → 유휴 시 로딩 → 토글")에 그대로 부합. **#33의 유휴 시 백그라운드 1회 처리 패턴 재사용**.

1. **추출**: `ExifInfo`에 `lat/lon/alt` 추가, kamadak GPS 태그로 읽기(기존 폴백 그대로).
2. **토글**: 단축키(예: `M`) + 설정 저장(`config.rs`, `#[serde(default)]`), **기본 off**. GPS 없으면 자동 미표시.
3. **지연 로딩**: 디코딩·프리페치·진행작업·모달이 **모두 끝난 유휴 상태**에서만 백그라운드 스레드 시작
   (#33 `maybe_check_update`와 동일 조건). 사진 보기 속도 영향 0.
4. **타일 취득**: 현재 사진 좌표를 Web Mercator로 환산해 해당 타일 `z/x/y` 계산 →
   `ureq`로 `https://tile.openstreetmap.org/{z}/{x}/{y}.png` 소수 장 받기 → egui 텍스처로.
5. **표시**: 한쪽 코너 작은 미리보기 패널(타일 + 위치 마커 점). 클릭 시 외부 브라우저로 크게 보기(3장 URL).
   **"© OpenStreetMap contributors" attribution 표기 필수**(OSM 정책).
6. **캐싱**: 받은 타일은 **기존 썸네일 디스크 캐시 인프라 재활용** → 재요청 최소화(정책상 캐싱 의무도 충족).

### 처음엔 작게
- 팬/줌 풀 기능은 타일 관리·드래그 구현이 더 붙음(공수↑). **1차는 정적 미리보기(줌 1~2단계 고정)**,
  세밀히 보고 싶을 땐 외부 브라우저로 넘기는 조합이 비용 대비 효과 좋음.

## 5. Windows 빌드 PC 검증 체크리스트

> 개발기엔 GPS 사진이 없음. 아래는 **GPS 태깅된 사진**으로 확인.

1. **GPS 있는 사진 확보**: 폰으로 찍은 JPG/HEIC, 또는 LUMIX Sync 등으로 지오태깅한 RW2, GPS 내장 바디 RAW.
2. **추출 확인**: 그 파일에서 위경도가 EXIF에 잡히는지(ExifTool로 교차검증: `exiftool -GPS* 파일`).
3. **포맷별 확인**: JPG / RW2(임베디드 JPEG 경로) / 다른 RAW에서 모두 좌표가 나오는지.
4. **반구 기호**: 남반구(S)/서경(W) 사진이 있으면 부호가 맞는지(없으면 좌표 수동으로 부호 바꿔 테스트).
5. **타일 표시**: 네트워크 연결 상태에서 좌표 주변 OSM 타일이 받아져 마커 위치가 실제 촬영지와 맞는지.
6. **오프라인/실패**: 네트워크 없을 때 앱이 멈추지 않고 조용히 미표시되는지(#33과 동일 격리).

## 6. 라이센스·정책 관점 (중요)

- **코드 의존성**: 권장안은 신규 코드 의존성 0(ureq는 #33에서 이미 추가). `walkers`는 MIT지만 tokio 트리 → 회피.
- **지도 데이터/타일**: OSM 데이터는 **ODbL**, 타일 사용은 [OSMF 타일 정책] 적용.
  - User-Agent 명시 필수(이미 #33에서 `RawBlow/버전` 사용 중).
  - **attribution "© OpenStreetMap contributors" 표기 필수**.
  - 벌크 다운로드 금지(마커 주변 소량은 허용 범위). **상업 배포 시 접근 차단 위험 명시** — 무료 개인 배포인 현재는 허용 범위.
- 참고: 본 저장소의 **RAW 디코더가 LGPL**이라는 별개의 라이센스 이슈가 있음 → `docs/licenses-audit.md`(별도) 참조.

## 7. 미결정 사항 (오너 확정 필요)

1. **표시 방식**: 인앱 정적 지도(권장) vs 외부 링크만 vs 둘 다.
2. **토글 단축키/위치**: `M` 등 단축키 + 어디에 패널을 띄울지(코너 오버레이 vs EXIF 패널 옆).
3. **OSM 직접 호출 수용 여부**: 정책상 차단 위험을 감수할지(현재 규모는 무난).
4. **팬/줌 범위**: 정적 미리보기로 시작 vs 처음부터 드래그 가능한 지도.
