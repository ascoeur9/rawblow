## 0. 핵심 결론 (먼저)

- **파인튜닝·별도 ML 학습은 필요 없다.** CLIP 백본은 **동결**하고, 그 위에 **작은 개인 취향 헤드**만 학습한다.
- 취향 헤드 = **선형 헤드(로지스틱 회귀)**, 조정 파라미터 ~513개. **CPU 1초 미만, GPU/고사양 불필요.**
- 학습 데이터는 따로 만들지 않는다 — **평소의 Pick/Reject/별점이 곧 라벨**.
- "셀렉한 파일 학습하기" 버튼 = **online personalization**의 정석. 누를수록 똑똑해진다.
- M5 Max 128GB는 파인튜닝이 아니라 **큰 백본(ViT-L/14) export·임베딩 추출**에 쓰면 충분.

> 한 줄 요약: **파인튜닝 = 눈을 다시 교육(거대·위험). 선형 헤드 = 눈은 그대로 두고 취향만 얹기(작고 안전).**

## 1. 아키텍처 — 동결된 CLIP + 개인 선형 헤드

```
[사진] ─► CLIP 이미지 인코더(동결) ─► 임베딩 512d(또는 768d)  ─(캐시)
                                              │
                                              ▼
                                    선형 헤드:  score = sigmoid(w·embed + b)
                                              │
                                              ▼
                                    "이 사진을 좋아할 확률" ─► 컬링 랭킹/Top-N Good
```

- **CLIP(눈)** = 이미 학습 완료, 절대 안 건드림. 사진을 "512차원 공간의 점"으로 바꿔주는 역할.
- **선형 헤드(취향)** = `w`(가중치 벡터) + `b`(편향). `w`는 그 공간에서 **"내 취향 방향을 가리키는 화살표"**.
- 곧은 칸막이(초평면)로 충분한 이유: CLIP이 이미 개념을 정렬해놨기 때문. 픽셀이 아니라 정돈된 의미공간을 가르는 일.

### 현재 코드와의 연결
- 지금 `AestheticModel`(`quality.rs:493`)은 `"Good photo."/"Bad photo."` 프롬프트를 그래프에 구워넣은 **제로샷**.
  → 출력을 **정규화된 이미지 임베딩**으로 바꿔 export(`feats = feats/feats.norm(...)`를 그대로 출력).
  `scripts/research/README.md:47`에 이미 "이미지 임베딩 출력형으로 export" 예고됨.
- 점수가 `finalize_cull_verdicts`(`quality.rs:439`)의 `aesthetic` 자리에 들어가던 것을 **개인 취향 점수**로 대체.

## 2. 데이터 플로우 — 임베딩 + 영구 라벨 창고

폴더를 갈아끼우는 사용 패턴에서 데이터가 날아가지 않으려면, **로드된 사진과 별개로 라벨을 영구 보관**해야 한다.

```
폴더 A 컬링 → 셀렉분 (임베딩, 라벨, 셀렉시각, 신호종류)  ┐
폴더 B 컬링 → 〃                                          ├─► [영구 라벨 창고] (계속 누적)
폴더 C 컬링 → 〃                                          ┘            │
                                                                       ▼
                                                            여기서 학습 (전 폴더 전체)
```

- 창고에는 **원본이 아니라 임베딩(≈2KB) + 메타**만 저장. 10만 장 ≈ 200MB. 평생 모아도 가볍다.
- **원본/폴더가 닫혀 있어도 학습 가능**(임베딩이 창고에 있으므로).
- **백본 ID를 키에 포함** → 백본 바꾸면 임베딩·헤드 무효화(차원·의미가 달라짐).
- 위치: `cache.rs` 캐시 옆에 별도 저장소(파일 포맷은 단순 append 가능한 형태 권장).

### "전체 재학습" vs "증분"
- **전체 재학습(+영구 창고)** = 매번 전 폴더를 똑같이 다시 봄 → **옛 취향 보존, 잘못된 라벨 취소 가능, 단순**. → **기본 채택.**
- **증분(창고 없이 w만 갱신)** = 빠르지만 **최근 편향(recency drift)**으로 옛 취향이 서서히 잊힘 + 취소 불가.
- 결론: "데이터 안 날아가게"의 해법은 *증분*이 아니라 **영구 창고**다. 창고만 있으면 전체 재학습이 더 안전.

## 3. 학습 — 로지스틱 회귀 (+ centroid 대안)

### 무엇이 "학습"인가
`w`, `b`를 데이터에 맞게 찾는 것. 반복:
1. 예제 한 장 점수 계산 → 2. 실제 라벨과 비교(오차) → 3. 오차 줄이는 쪽으로 `w,b` 미세 조정 → 4. 전 예제로 수백 번 반복(경사하강).
- 조정 대상 ~513개 + 데이터 수백 장 → **순수 Rust·CPU로 1초 미만.** 결과물 = 514개 float 파일 하나.

### 콜드 스타트
- `w` 초기값 = **(Good 텍스트 임베딩 − Bad 텍스트 임베딩) 방향**.
  → 라벨 0개일 때 *지금과 동일*하게 동작, 라벨 쌓일수록 사용자 쪽으로 휨. 끊김 없는 개인화.
- 데이터 적을 때(예: 셀렉 5장)는 시간/중복 가중을 **약하게**(또는 하한선) 둬서 학습 굶주림 방지.

### 1단계 대안 — centroid (학습 없이 시작)
- 좋아한 사진 임베딩의 **평균점(centroid)** 과의 **코사인 유사도**로 채점.
- 곱셈·평균만, 반복 학습 없음. 좋아요 10~20장이면 체감. **negative 불필요** → "셀렉만으로 시작"에 적합.
- 데이터 쌓이면 **2단계(선형 헤드)** 로 승급.

## 4. 가중치 설계 — 세 자리(層)

가중치가 살 수 있는 자리는 세 군데다. ①이 본체.

```
① 예제 가중(sample weight)  — 학습 예제 하나가 "얼마나 중요한가"   ← 설계의 주 무대
② 특징 가중(feature weight) — 512차원 각각 = w(자동 학습). 손 안 댐. 레버는 "장르별 헤드 분리"뿐
③ 융합 가중(fusion)         — 취향 vs 기술품질 vs 게이트를 어떤 비율로 섞나
```

### ① 예제 가중 — 통합 공식
```
예제 가중 = 시간감쇠
          × 신호세기(A)
          × 하드네거티브 보너스(C)
          ÷ √클러스터크기(D)
          ÷ 클래스불균형 보정
```
+ 별도 스트림: **쌍 차이 예제(C-2)** 를 같은 헤드에 추가 학습.

#### 시간 — 취향 변화 반영
- `예제 가중 = decay^(오늘 − 셀렉시각)`. 반감기(half-life)가 다이얼: ∞=전체기억, 짧게=최근위주.
- **저장은 "셀렉(라벨링)한 날짜"** — 촬영(EXIF) 날짜가 아님. 취향 타임라인은 "표현한 시점".
- 원본 예제를 다 들고 있으므로 **반감기를 나중에 언제든 재조정** 가능(증분과 결정적 차이).

#### A. 신호 세기 — 행동을 신뢰도로 번역
- **방향(positive/negative=정답)** 과 **세기(확신=가중)** 를 분리.
- 표현 방법 2가지(병용 가능):
  - 가중치: 라벨 1, 무게만 차등.
  - **소프트 라벨(추천)**: 목표를 확률로. export 0.95 / 별5 0.90 / 별3 0.70 / Reject 0.10 / 삭제 0.02.
- **행동 사다리(노력=신뢰도)**: export·납품 ≫ 보정/리터칭 ≫ 앨범커버 ≫ 확대열람(암묵) ≫ 별점/Pick.
- **최대 함정**: "아무 행동 없음 = negative ❌". 그건 *결측*이다. **컬링을 끝까지 마친 폴더의 미선택만** *약한* negative.
  → "컬링 완료" 상태 기록이 negative 수집의 전제.
- 보정은 거칠게: 강/중/약 = 3/2/1로 시작.

#### C. 하드 네거티브 — 연사/근접중복에서 "하나만 고른" 차이 (백미)
- `group_bursts`·`cluster_near_dups`로 거의 동일한 묶음 확보 → 그 안의 **고름 vs 버림** 쌍이 취향 경계를 가장 날카롭게 가르침.
- **C-1(쉬움)**: positive와 임베딩이 가까운 negative를 **upweight**.
- **C-2(고급·쌍 차이 학습)**: "A(고름)가 B(버림)보다 낫다"를 학습.
  - 선형 헤드에서 `점수A − 점수B = w·(embA − embB)` (b 상쇄).
  - ⇒ **차이벡터 `(embA−embB)`를 입력, 라벨 항상 1**인 로지스틱 회귀와 *정확히 동일*. **같은 학습 코드 재사용.**
  - 공통(같은 장면·구도)은 뺄셈으로 상쇄, **고른 차이 방향만** 순수 추출.
  - 절대 예제 + 차이 예제를 **한 학습에 혼합** 가능(비율이 또 하나의 손잡이).
  - 쌍 생성: 킵 2 · 버림 8 → `2×8=16`쌍. 킵끼리·버림끼리는 신호 없음.
- **⚠️ 한계**: CLIP이 그 차이를 "볼" 때만 유효.
  - 구도·표정·미감·분위기 → CLIP 봄 → 유효 ✅
  - 눈감음·미세 초점 → CLIP 잘 못 봄 → 노이즈 ❌ → **객관 지표/얼굴검출에 맡길 것**(§5 역할분담).

#### D. 중복 다운가중 — "찍은 것 ≠ 좋아하는 것"
- 표본 편향: 여행으로 해변 300장 ⇒ 모델이 "해변충"으로 기울어짐.
- 두 스케일: **연사 중복**(dHash로 잡힘) / **주제 중복**(여러 날 해변 — dHash로 안 잡힘 → **임베딩 공간 밀도 클러스터링** 필요).
- 처방: `예제 가중 ∝ 1/√클러스터크기`(부드럽게). 1/n은 과함.
- **딜레마**: 진짜 "해변 사진가"면 누르는 게 틀림 → √ 또는 하한선으로 "줄이되 지우지 않기".
- ②의 장르별 헤드 분리와 궁합: 장르 *간* 불균형은 분리가 해결, D는 장르 *안* 중복만 처리.
- **C와 D는 짝**: 같은 연사에서 *절대 신호는 1장처럼*(D) + *킵>버림 쌍은 전부 살림*(C). 중복은 깎고 차이는 살림.

### ② 특징 가중 — 대부분 자동
- `w` 자체가 차원별 가중치 → **학습이 알아서 찾음. 손대지 말 것.**
- 유효한 레버: **장르별 헤드 분리**(`genre_portrait` 축으로 인물/풍경 가른 뒤 각각 별도 `w`). 인물·풍경 취향이 다름.

### ③ 융합 가중 — 취향 vs 기술품질 vs 게이트
```
최종 점수 = α·(개인 취향) + β·(기술 품질: focus/exposure/tilt) + 하드필터(메타·연사베스트·중복)
```
- 권장 구조: 기술적으로 망한 것(심한 블러·노출 날아감)은 **하드 게이트로 컷**, 그 위에서 **취향으로 랭킹**.
- Tier1–3a(메타·연사·중복)는 가중이 아니라 **통과/탈락 게이트**로.

## 6. 검증 — "취향 모델이 잘 됐나"를 어떻게 아나

- **홀드아웃**: 최근 셀렉 N장(예: 20)을 학습에서 빼두고, 학습된 모델이 그것을 **상위로 랭킹하는지** 확인.
- 검증 없이는 가중치 = 깜깜이 하이퍼파라미터. **한 번에 하나씩** 추가하며 효과 측정.
- 거칠게 시작(3/2/1, √n, 강/중/약) → 검증 보며 정밀화.

## 7. 단계적 도입 로드맵

1. **모델 교체**: `export_clip_axes.py` 변형으로 **임베딩 출력형 ONNX** export(백본 선택: ViT-B/32 빠름 vs ViT-L/14 정확).
2. **임베딩 캐시 + 영구 라벨 창고**(백본 ID 키 포함).
3. **1단계 personalization = centroid**(학습 없이, negative 불필요) — "셀렉한 파일 학습하기" 버튼.
4. **2단계 = 선형 헤드**(로지스틱 회귀, 콜드스타트 = Good−Bad 방향).
5. 가중치 순차 투입: **시간 + A(신호세기)** → **C-1(하드네거티브 upweight)** → **D(√ 다운가중)** → **C-2(쌍 차이 학습)**.
6. **③ 융합 + §5 역할분담** 배선, 검증(§6) 상시.

## 8. 주의·미해결

- **백본 변경 시 캐시·헤드 전면 무효화**(키에 백본 ID).
- **장르별 취향 차이** → 단일 `w`가 어정쩡하면 헤드 분리.
- **라벨 노이즈**: 오클릭 가능 → 단일 행동에 과한 가중 금지, downstream-confirmed(export)일수록 신뢰.
- **negative 희소**: 클래스 균형 보정 + "컬링 완료" 전제.
- **과적합/과설계**: 손잡이 남발 금지, 검증 셋 필수.
- **라이선스**: 사용자 사진으로 로컬 학습한 헤드는 OpenAI CLIP(MIT) 번들 정책과 무관(사용자 데이터·기기 내).
- **주제 중복 클러스터링 비용**: 임베딩 공간 클러스터링(k-means/밀도) 도입 시점·주기 미정.
