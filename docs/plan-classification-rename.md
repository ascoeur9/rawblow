## #27 — 추가 분류축 (Additional classification axis)

### 배경
현재 분류축은 **라벨**(Pick/Hold/Reject/Unrated — QWER 단일선택)과 **별점**(★1–5 — 숫자키, 라벨과 독립 AND)이다.
테스터 니즈: 같은 등급(예: A컷) 안에서도 **보정 방식**으로 더 나누고 싶다 — `템플릿만` / `한땀한땀` / `무템플릿` 등.
즉 라벨·별점과 **직교(독립)** 하는 **제3의 축**이 필요하다.

### 옵션
| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 컬러 태그**(권장) | Lightroom식 색 라벨 5색(Red/Yellow/Green/Blue/Purple) 단일선택 + 설정에서 색별 **이름 지정** 가능(예: Green=템플릿) | 컬링 워크플로(키 한 번)에 딱 맞음, 시각적(썸네일 점), 유한 집합, 영속화 단순(enum), 이름 지정 시 자기설명적 | 색=의미를 사용자가 정의해야, 개수 고정(5) |
| B. 명명 카테고리 | 사용자 정의 카테고리 N개 단일선택 | 이름이 명시적 | 카테고리 관리 UI 필요, 복잡 |
| C. 자유 태그(멀티) | 임의 문자열 다중 태그 | 최대 유연 | 키보드 컬링과 안 맞음(자유입력), 과설계 |

### 권장안 — **컬러 태그(이름 지정 가능)**
- 5색 **단일선택**(라벨·별점과 독립). 기본은 색 이름, 설정에서 색별 커스텀 이름(예: `템플릿`/`수작업`/`무템플릿`)을 붙이면 레일·필터·전송에 그 이름이 표시됨.
- 라벨(분류 의도)·별점(품질)·태그(처리 방식)의 3축이 깔끔히 분리된다.

### 데이터모델·영속화 영향
- `model.rs`: `enum ColorTag { None, Red, Yellow, Green, Blue, Purple }`(또는 `u8` 0–5), `Entry.tag: ColorTag` 추가, `color_rgb()`/`name(lang)`.
- `sidecar.rs`: `ItemRec`에 `#[serde(default)] tag: ColorTag` 추가 → **구버전 세션 호환**(별점 도입 때와 동일 패턴). `save`의 "Unrated+0★ 생략" 가드를 "태그만 있어도 보존"으로 확장. `apply`/`render_txt`에 태그 섹션.
- `config.rs`: `tag_names: [String; 5]`(빈 문자열이면 색 이름 표시) + 키맵 항목.

### 구현 단계
1. 모델·영속화: `ColorTag` + `Entry.tag` + 사이드카 round-trip(+테스트).
2. 입력·표시: `set_tag()`, 키 바인딩(별점이 1–5를 쓰므로 **빈 키** 사용 — 예: `A S D F G` 또는 `Shift+1–5`), 좌측레일 `Color` 섹션(5색 점+카운트), 그리드 다중선택 일괄 적용.
3. 필터: 태그 필터(별점 필터처럼 독립 AND) — `model.rs` + 레일 UI.
4. 전송: `split_by_tag` 옵션(태그별 하위폴더) — `transfer.rs`.
5. 설정: 색별 커스텀 이름 입력 UI.
6. i18n(#30): 신규 문자열 번역(ko/en/ja).

### 확정된 결정 (2026-06-03)
- ✅ **컬러 태그(단일선택)** 채택 (5색, 라벨·별점과 독립 AND).
- ✅ **커스텀 이름 이번에 포함** — 설정에서 색별 이름 지정, 레일·필터·전송에 반영.
- 🔸 입력 키(제안, 이견 없으면 확정): **Shift+1–5**로 5색 부여(별점 1–5와 짝이 맞아 기억 쉬움), `Shift+0` 또는 ``Shift+` ``로 해제.

## #26 — 분류 기반 파일명 변경 (Rename by classification)

### 배경(대화 캡처 정리)
- 셀렉한 파일을 **선택 순서대로 번호**(1,2,3,4…) 부여, **또는**
- **별점 기준 등급+순번**: 5★→A1 A2 A3…, 4★→B1 B2 B3… (등급 문자 + 등급 내 순번).
- 목적: 파일명만으로 등급/순서 정리가 쉬워짐.
- 이슈 단서: 규칙/템플릿/범위 제공 방식, **즉시 리네임 vs 복사·이동 시에만**, **위험성** 고려 필요.

### 핵심 리스크
- **즉시(in-place) 리네임은 파괴적·비가역**: RAW+JPG 페어를 같은 stem으로 함께 안 바꾸면 페어 깨짐, 사이드카(stem 키) 무효화, 이름 충돌, 되돌리기 어려움, OS 파일 잠금.
- **충돌**: 둘 이상이 같은 새 이름 → 충돌 정책 필요(이미 `unique_path` 존재).
- **페어링**: RAW/JPG는 stem 공유 → 한 항목의 모든 member를 **같은 새 stem**으로(확장자 유지).
- **사이드카 정합성**: 리네임 후 stem 키가 어긋남.

### 템플릿 설계(토큰)
- `{seq}` 순번(패딩 `{seq:03}`), `{grade}` 등급문자(5★=A … 1★=E), `{gradeseq}` 등급+등급내순번(A1,B2…=대화 요구), `{stars}` 숫자별점, `{label}` 라벨명, `{orig}` 원본 stem, (후속) `{date}`/`{camera}` EXIF.
- **번호 기준**: ① 선택/정렬 순서(1,2,3…) ② 등급 그룹(별점 내림차순으로 A1,A2…,B1…).
- **범위**: 선택 항목 / 필터된 보기 / 전체.

### 안전 전략 — **2단계(권장)**
**1단계(우선): 전송 시 리네임 (rename-on-transfer)** — 기존 Transfer(Copy/Move)에 리네임 템플릿을 추가.
- **안전**: Copy면 원본 무손상, 새 대상 폴더라 사이드카 영향 없음, 기존 `execute()`의 충돌(`unique_path`)·페어(`select_members`)·`report.renamed` 재사용.
- 대화의 실제 시나리오(베스트컷을 새 폴더에 A1/A2…로 정리)를 **그대로 충족**.

**2단계(후속, 강한 가드): 즉시 리네임 (in-place)** — 별도 액션으로, 다음 안전장치 필수:
- **드라이런 미리보기**(old→new 표) 후 적용, **되돌리기 로그**(`.rawblow/rename-log.json`), **사이드카 stem 갱신**, **페어 동시 변경**, **충돌 사전검사**(중복 대상이면 중단).

### 구현 단계(1단계)
1. `transfer.rs`: `TransferRequest.rename: Option<RenameRule>`, `RenameRule { template, numbering: {Order|GradeGrouped} }`. `plan()`/`execute()`에서 항목별 순번(+등급별 카운터) 부여 → 템플릿으로 새 stem 산출 → **항목의 모든 member에 동일 적용**(확장자 유지) → 충돌 정책 유지 → `report.renamed` 기록. `render_name()` + 토큰 파서.
2. `app.rs`(전송 다이얼로그): `Rename` 섹션 — 프리셋(`순번(1,2,3)` / `별점등급(A1,B1…)` / `원본 유지`) 또는 템플릿 입력, 번호기준 토글, **앞 N개 old→new 라이브 프리뷰**.
3. 등급 매핑(5★=A … 1★=E; 0★ 처리 결정), i18n 신규 문자열.
4. 테스트: 템플릿 렌더, 등급그룹 순번, 페어 동일 stem, 충돌 정책.

### 확정된 결정 (2026-06-03)
- ✅ **1단계 전송 시 리네임 먼저**, 즉시(in-place) 리네임은 후속(드라이런·undo·사이드카 갱신 갖춘 뒤).
- ✅ **프리셋 + 자유 템플릿 둘 다** — 프리셋(`순번(1,2,3)`/`별점등급(A1,B1…)`/`원본 유지`)으로 쉽게, 고급 사용자는 토큰 직접 입력.
- 🔸 등급 매핑(제안): **A=5★, B=4★, C=3★, D=2★, E=1★**. 0★(무별점)은 등급 모드에서 **제외**(전송은 되되 리네임 없이 원본명 유지) — 이견 없으면 확정.
