# 개발 기획 — 새 릴리즈 안내 (#33)

> 상태: **구현됨 (v0.4.3)**. 아래는 원 기획안이며, 실제 구현은 오너 확정에 따라 정해졌다.
> 코드 근거: `app.rs`(`maybe_check_update`/`fetch_latest_release_tag`/`parse_semver`/`newer_version`,
> 좌측 레일 배너), `Cargo.toml`(`ureq` optional + `update-check` 기능).

## 구현 결정 (오너 확정 · 2026-06)

- **시점**: 설정·시작 프롬프트가 아니라, **실행 후 모든 로딩이 끝나고 유휴 상태일 때 세션당 1회** 자동 확인
  (디코딩/프리페치·진행 작업·모달이 모두 없을 때). 별도 설정 토글 없음.
- **HTTP**: `ureq`(rustls, 루트 인증서 번들) — `update-check` 기능(기본 on). rustls(ring)는 C 컴파일이
  필요해 cc 없는 환경에선 `--no-default-features`로 끄고 나머지를 검증한다.
- **UX**: 새 버전이 있으면 **좌측 레일의 정리 버튼 바로 위**에 🎉 큰 강조 버튼으로 "새로운 버전이
  있습니다 (vX.Y.Z)"를 띄우고, 클릭 시 Releases 페이지를 브라우저로 연다(클릭하면 배너 닫힘). 강제 업데이트 아님.
- **버전 비교**: `parse_semver`로 `vX.Y.Z`(프리릴리스/빌드 메타 허용) 파싱 후 현재(`CARGO_PKG_VERSION`)와 튜플 비교.
- **에러/프라이버시**: 네트워크 실패·rate limit·파싱 실패는 조용히 무시. 호출은 백그라운드 스레드 1회뿐.

---

## 배경

- 현재 새 버전이 릴리즈돼도 사용자가 알 방법이 없음. 사용자가 직접 GitHub Releases를 확인해야 함.
- 설정 화면에는 이미 **"최신 버전 받기 · GitHub Releases"** 링크가 있으나, **새 버전이 있는지**는
  알려주지 않음(항상 같은 링크만 노출).
- 목표: 앱이 최신 릴리즈 버전을 확인해, **현재 버전보다 새 버전이 있을 때만** 안내(배지/문구)함.

## 핵심 제약

1. **HTTP 클라이언트 의존성이 전혀 없음.** 새 릴리즈 확인은 네트워크 호출이 필요 → 의존성 추가가 전제.
2. **단독 실행 바이너리 철학**(README: "설치·런타임 불필요"). 무거운 런타임(tokio 등)·동적 링크는 지양.
   Windows는 `+crt-static`로 단독 exe를 만들고 있어, TLS도 정적 링크 가능한 스택(rustls)이 적합.
3. **프라이버시**: 외부 서버(GitHub)로 나가는 네트워크 호출이 새로 생김. 사용자 인지·동의(옵트인/옵트아웃) 고려 필요.

## 확인 대상 API

- GitHub Releases: `GET https://api.github.com/repos/ascoeur9/rawblow/releases/latest`
  - 응답 JSON의 `tag_name`(예: `v0.5.0`)이 최신 릴리즈 태그.
  - **User-Agent 헤더 필수**(없으면 403). 비인증 호출 rate limit = IP당 60회/시 — 개인 앱엔 충분.
  - prerelease는 `/latest`에 안 잡힘(정식 릴리즈만) → 안내 기준으로 적절.
- 현재 버전: `env!("CARGO_PKG_VERSION")`(워크스페이스 `version`과 동일).
- 버전 비교: `vX.Y.Z` 파싱 후 (major, minor, patch) 튜플 비교. 별도 semver 크레이트 없이 직접 파싱 가능
  (태그 포맷이 단순·일관). 같거나 낮으면 안내 안 함.

## 옵션 비교

### HTTP 라이브러리
| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **ureq + rustls**(권장) | 동기 HTTP, 순수 Rust TLS | 가벼움, 정적 링크 친화(crt-static과 궁합), 동기라 백그라운드 스레드 한 번이면 충분, tokio 불필요 | 의존성 트리 일부 증가(rustls/ring) |
| minreq | 초경량 HTTP(+rustls feature) | 최소 의존성 | 기능 빈약, 헤더·타임아웃 제어 제한적 |
| reqwest | 사실상 표준 | 기능 풍부 | tokio 런타임 필요 → 무겁고 단독 바이너리 철학과 충돌 |
| 직접 TLS(std+rustls) | 의존성 최소 | 통제력 최대 | HTTP/TLS 직접 구현 부담, 유지보수 비용 |

→ **ureq(rustls 백엔드)** 권장. 동기 호출을 `std::thread`에서 1회 수행 후 결과만 채널/플래그로 UI에 전달
(앱은 이미 `crossbeam-channel`·백그라운드 워커 패턴을 사용 중 → 동일 패턴 재사용).

### 확인 시점
| 옵션 | 내용 | 비고 |
|---|---|---|
| **설정의 "업데이트 확인" 버튼**(권장 1순위) | 사용자가 누를 때만 호출 | 프라이버시 부담 없음, 구현 단순, 네트워크 호출이 명시적 |
| 시작 시 자동(빈도 제한) | 앱 시작 시 N일 1회 백그라운드 확인 | 편의성 높음. 단 옵트인/옵트아웃·빈도·프라이버시 문구 필요 |
| 둘 다 | 수동 버튼 + (옵션)자동 | 권장 최종 형태 |

### 빈도/캐시(자동 확인 시)
- `config.json`에 `last_update_check`(타임스탬프)·`latest_known_version`을 저장 → **1일 1회**만 실제 호출,
  그 외엔 캐시된 결과로 배지 표시. (`config.rs`에 필드 추가, `#[serde(default)]`로 구버전 호환.)

## 권장안 (요약)

- **의존성**: `ureq`(rustls feature) 추가.
- **1단계(우선)**: 설정 화면에 **"업데이트 확인"** 버튼 → 백그라운드 스레드에서 `/releases/latest` 호출 →
  새 버전이면 "vX.Y.Z 사용 가능" 문구 + 기존 GitHub Releases 링크(이미 있는 `open_url`) 강조.
- **2단계(옵션, 옵트인)**: 시작 시 1일 1회 자동 확인. 기본 on/off는 **미결정**(아래 참조). 새 버전이면
  툴바/설정에 작은 배지. **강제 업데이트 아님**(안내만).
- **에러 처리**: 네트워크 실패·rate limit·파싱 실패는 **조용히 무시**(앱 동작에 영향 0, 토스트도 선택적).
- **i18n(#30)**: 신규 문자열 ko/en/ja 동시 추가("업데이트 확인", "최신 버전입니다", "vX.Y.Z 사용 가능" 등).

## 데이터모델·영속화 영향

- `config.rs` `Config`에 추가(모두 `#[serde(default)]` — 구버전 config 호환):
  - `auto_update_check: bool`(자동 확인 on/off)
  - `last_update_check: Option<i64>`(마지막 확인 시각, epoch sec)
  - `latest_known_version: Option<String>`(마지막으로 확인한 최신 태그 — 오프라인에서도 배지 유지)

## 미결정 사항 (오너 확정 필요)

1. **ureq 의존성 추가 승인 여부** — 단독 바이너리 철학상 OK인지(rustls/ring 포함).
2. **자동 확인 기본값** — 기본 on(옵트아웃) vs 기본 off(옵트인). 프라이버시 관점에서 **기본 off + 첫 실행 안내** 권장.
3. **확인 주기** — 1일 1회(권장) vs 매 실행 vs 수동만.
4. **프라이버시 문구** — "GitHub에 최신 버전을 확인합니다"류 안내를 설정에 노출할지.

## 검증 계획(구현 전 사전 확인)

- GitHub API 응답 포맷·rate limit 실측(User-Agent 유무에 따른 403 재현).
- 오프라인/사설 네트워크/프록시 환경에서 **앱이 멈추거나 느려지지 않는지**(타임아웃·백그라운드 격리 확인).
- Windows 정적 링크 빌드에서 rustls/ring가 `+crt-static`과 충돌 없이 빌드되는지(빌드는 Windows에서 검증).

## 구현 단계(승인 후)

1. `Cargo.toml`(app)에 `ureq`(rustls) 추가. core가 아닌 **app** 계층에 둠(네트워크는 UI 부수기능).
2. 버전 비교 유틸(`vX.Y.Z` 파서 + 튜플 비교) + 단위테스트.
3. 백그라운드 확인(스레드 + 채널) → 결과를 앱 상태에 반영.
4. 설정 UI "업데이트 확인" 버튼 + 결과 문구/배지. (2단계) 자동 확인 + config 필드.
5. i18n(ko/en/ja) 신규 문자열.
